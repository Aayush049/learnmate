1. EXECUTIVE SUMMARY & CORE OBJECTIVES
================================================================================

LEARNMATE's Performance Analysis Engine bridges raw assessment outcomes (mock
tests, PYQ practice, topic quizzes) with continuous study behavior (reading time,
revision frequency, consistency streaks).

Key Objectives:
1. Latent Mastery Estimation: Accurately separate genuine student concept mastery
   from lucky guesses and careless slips using Bayesian Knowledge Tracing (BKT).
2. Cognitive Profiling: Classify mistakes into "Conceptual Gaps", "Careless Slips",
   "Overthinking/High Cognitive Load", and "Speed Traps" using topic-normalized
   time-per-question analytics.
3. Root Cause Attribution: Correlate test failures against historical study time
   to tell students whether they need more practice (Knowledge Gap) or conceptual
   re-training (Misunderstanding).
4. Predictive Modeling & Burnout Guard: Forecast upcoming mock exam scores and
   detect sudden drops (> 2 sigma) via Welford's algorithm to alert against fatigue.
5. High Performance: Maintain < 100ms API response times by maintaining
   incrementally updated summary tables on test submission rather than running
   expensive scans on dashboard load.

5. DIAGNOSTIC CORE & MATHEMATICAL SPECIFICATIONS
================================================================================

--------------------------------------------------------------------------------
5.1 Bayesian Knowledge Tracing (BKT)
--------------------------------------------------------------------------------
BKT tracks a student's binary latent knowledge state $L_t \in \{0, 1\}$ (Unmastered / Mastered)
across sequential question attempts on topic $k$.

Parameters (Standard Priors for 4-Option SSC JE MCQs):
- $P(L_0) = 0.10$ : Prior probability of initial topic mastery.
- $P(T)   = 0.15$ : Probability of learning/transitioning on a question attempt.
- $P(G)   = 0.20$ : Probability of a lucky guess on 4-option MCQ (penalty-adjusted).
- $P(S)   = 0.10$ : Probability of a careless slip on a known question.

Update Algorithm:
Step 1: Compute posterior probability given observed response $O_t \in \{1=\text{Correct}, 0=\text{Incorrect}\}$:

If Correct ($O_t = 1$):
                      P(L_{t-1}) * (1 - P(S))
  P(L_t | O_t=1) = ---------------------------------------------
                   P(L_{t-1}) * (1 - P(S)) + (1 - P(L_{t-1})) * P(G)

If Incorrect ($O_t = 0$):
                      P(L_{t-1}) * P(S)
  P(L_t | O_t=0) = ---------------------------------------------
                   P(L_{t-1}) * P(S) + (1 - P(L_{t-1})) * (1 - P(G))

Step 2: Apply Learning Transition Step:
  P(L_{t+1}) = P(L_t | O_t) + (1 - P(L_t | O_t)) * P(T)

Clamp output: $P(L_{t+1}) \in [0.01, 0.99]$.

--------------------------------------------------------------------------------
5.2 Cognitive Load Profiling (Topic-Relative Time Index - RTI)
--------------------------------------------------------------------------------
Static time limits fail because calculation questions (e.g., RCC Design) take
60-90s, while theoretical questions take 10-15s.

1. Benchmark Derivation:
   Compute the platform median time $\mu_{\text{topic}}$ and standard deviation
   $\sigma_{\text{topic}}$ across all historical attempts for that topic.
   (Fallbacks: Theory $\mu=25s, \sigma=10s$; Calculation $\mu=65s, \sigma=25s$).

2. Relative Time Index (RTI z-score):
          t_{user} - \mu_{topic}
  RTI = --------------------------
             \sigma_{topic}

3. Quadrant Classification:
  +----------------------+--------------------+--------------------------------+
  | Condition            | Quadrant           | Pedagogical Diagnosis          |
  +----------------------+--------------------+--------------------------------+
  | RTI <= 0.0 & Correct | Quad 1: Fast Master| Fluent knowledge / Intuitive   |
  | RTI > 0.0 & Correct  | Quad 2: Methodical | Solid concept, needs speed rep |
  | RTI < -0.4 & Error   | Quad 3: Speed Trap | Rushed, slip, or blind guess   |
  | RTI >= -0.4 & Error  | Quad 4: High Load  | Conceptual struggle / confusion|
  +----------------------+--------------------+--------------------------------+

--------------------------------------------------------------------------------
5.3 Weighted Topic Mastery Index (TMI with Exponential Decay)
--------------------------------------------------------------------------------
TMI combines raw accuracy with recency decay so performance from 30 days ago
weighs less than performance from today.

  Half-life $T_{half} = 14\text{ days} \implies \lambda = \frac{\ln(2)}{14} \approx 0.0495\text{ days}^{-1}$.
  Weight for attempt $i$ at $\Delta t_i$ days ago:
    w_i = e^{-\lambda \cdot \Delta t_i}

  Decayed Accuracy:
           \sum_{i=1}^N (w_i \cdot \text{is\_correct}_i)
    A_d = -----------------------------------------------
                       \sum_{i=1}^N w_i

  Final TMI Formula:
    \text{TMI} = \left(0.60 \cdot P(L) + 0.40 \cdot A_d\right) \times 100 \in [0, 100]

--------------------------------------------------------------------------------
5.4 Performance Velocity & Score Trajectory
--------------------------------------------------------------------------------
For the last $K = \min(N, 8)$ mock test percentage scores $(s_1, s_2, \dots, s_K)$:
Compute linear regression slope $m = \frac{d(\text{score})}{d(\text{test})}$.

- $m > +1.5\text{ \%/test}$  $\implies$ **Accelerating** (Strong upward momentum)
- $-1.5 \le m \le +1.5$     $\implies$ **Plateauing** (Stable / Needs fresh challenge)
- $m < -1.5\text{ \%/test}$  $\implies$ **Regressing** (Declining / Needs intervention)

--------------------------------------------------------------------------------
5.5 Real-Time Anomaly & Burnout Detection (Welford's Algorithm)
--------------------------------------------------------------------------------
Welford's algorithm computes running mean and variance in $O(1)$ without storing
all past scores.

On new test score $x_k$ (where $k$ is test count):
  \Delta = x_k - \bar{x}_{k-1}
  \bar{x}_k = \bar{x}_{k-1} + \frac{\Delta}{k}
  \Delta_2 = x_k - \bar{x}_k
  M_{2,k} = M_{2,k-1} + \Delta \cdot \Delta_2
  \sigma_k = \sqrt{\frac{M_{2,k}}{k - 1}}  \quad (\text{for } k \ge 2)

SAFETY GUARDS:
1. Minimum Test Threshold: Anomaly detection remains **OFF** for $k < 5$.
2. Trigger Condition:
   Score $x_k$ is an Anomaly IF:
     \frac{x_k - \bar{x}_{k-1}}{\sigma_{k-1}} < -2.0 \quad \text{AND} \quad (\bar{x}_{k-1} - x_k) \ge 15.0\%
3. If Triggered:
   Flag profile as `burnout_flag = "Warning"`.
   Recommend reduced load: "Short 10-question confidence booster + 24hr break".

--------------------------------------------------------------------------------
5.6 Student Behavioral Archetype Classifier
--------------------------------------------------------------------------------
Rule-based scoring categorized after every 3 mock tests:

1. "The Crammer":
   - Study time concentrated in 48 hrs before test (>70% of total study).
   - High test score variance ($\sigma > 15$).
2. "The Perfectionist":
   - High accuracy (>80%), but high average time ($RTI > 0.8$).
   - Multiple unattempted questions due to running out of time.
3. "The Speedster":
   - Low average time ($RTI < -0.6$), high Quad 3 slip rate (>25% errors).
   - Negative marking penalty exceeds 10% of total score.
4. "The Steady Builder":
   - Consistent daily study sessions (streak $\ge 5$), steady velocity ($m \ge 0$).

| Test Performance  | Topic Study Time   | Root Cause Finding | Automated Recommendation               |

7. INCREMENTAL AGGREGATION PIPELINE (SUB-100MS LATENCY)
================================================================================

To guarantee blazing-fast dashboard loads:
1. On `POST /api/v1/mock-tests/submit` or `POST /api/v1/questions/submit`:
   - Enqueue a lightweight async background worker: `evaluate_performance_updates(user_id, attempt_ids)`.
2. The worker:
   - Fetches attempt details.
   - Runs BKT step updates on `user_topic_mastery`.
   - Increments cognitive load quadrant tallies.
   - Updates Welford's running stats in `user_performance_profiles`.
   - Updates velocity and archetype flags.
3. When the student opens the Dashboard, the backend performs a simple indexed query
   on `user_topic_mastery` and `user_performance_profiles` (Execution time: ~5-15ms).
